topbar rules:
• left/right event on topbar navigate from 1:1 to 1:4.
• ‘right’ on 1:4 cycle back to 1:1
• ‘down’ move to grid

grid rules:
• left/right event on grid navigate from 2:1 to 2:4.
• ‘right’ on 2:4 go to next line on 3:1
• ‘up’ while on 2:* move to topbar

Keybinds event on the topbar are handled by the providers
Keybinds event on the grid are handled by the controls

Stories:

I type “l” while on the document:
> matches the “l” keybind of the provider
• perform the “navigation:right” keybind on the topbar
• the input is not selected

I type “lll” while on the document:
> matches the “l” keybind of the provider
• perform the “navigation:right” 3 times on the topbar
• the input is not selected

I type “l” while on the grid:
> matches the “l” keybind of the control
• perform the “navigation:right” keybind on the grid
• the input is not selected

I type “lll” while on the grid:
> matches the “l” keybind of the control
• perform the “navigation:right” 3 times on the grid
• the input is not selected

I type “left” while on the document:
> matches the “l” keybind but “e” has no keybind in provider
• doesn’t perform any keybind 
• Success

I type “left” while in the grid:
> matches the “l” keybind but “e” has no keybind in control
• doesn’t perform any keybind 
• the input is selected and “left” is written in it.

I type “l” and then “e” 200ms later on the document:
> matches the “l” keybind but “e” has no keybind in control
• perform “l” keybind in the topbar
• the input is selected and “le” is written in it.

I type “l” and then “e” 200ms later on the grid:
> matches the “l” keybind but “e” has no keybind in control
• perform “l” keybind in the grid.
• the input is selected and “le” is written in it.
